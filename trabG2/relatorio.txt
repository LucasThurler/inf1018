Etapa 1 - Inspeção do prólogo/epílogo e instrução básica
---------------------------------------------------------
Compilamos a função assembly foo(int x) { return x; } para
inspecionar os bytes gerados pelo compilador.

Arquivo: foo.s
Comando: gcc -c foo.s -o foo.o && objdump -d foo.o

Resultado:
  55           push  %rbp        (prólogo)
  48 89 e5     mov   %rsp, %rbp  (prólogo)
  89 f8        mov   %edi, %eax  (corpo: repassa x como retorno)
  c9           leave             (epílogo)
  c3           ret               (epílogo)

Total: 8 bytes. Confirmamos o padrão de prólogo/epílogo
que cria_func deverá gerar.



Etapa 2 - Inspeção do call indireto e movabs
--------------------------------------------
O trabalho exige que cria_func gere dinamicamente o código de
uma função "wrapper" — func intermediária que recebe os argumentos
livres (PARAM), completa os amarrados (FIX/IND), e então chama
a função original f. Conforme orientação do professor na parte Dicas,
inspecionamos os bytes de um wrapper simples para entender quais
instruções de máquina precisaremos gerar.

Como o wrapper precisa chamar f sem saber seu endereço em tempo
de compilação, usamos call indireto (call *%rax), onde %rax
carrega o endereço de f em runtime. Para carregar um endereço
de 64 bits em %rax, usamos movabs — única instrução que comporta
um imediato de 64 bits completo.

Arquivo: mov_imm64.s
Comando: gcc -c mov_imm64.s -o mov_imm64.o && objdump -d mov_imm64.o

Resultado relevante:
  48 b8 + 8 bytes   movabs $endereço, %rax   (little-endian)
  ff d0             call   *%rax

Conclusão: para embutir o endereço de f no código gerado,
usamos os bytes 48 b8 seguidos dos 8 bytes do ponteiro em
little-endian (via memcpy). Combinando com prólogo/epílogo
da Etapa 1, mapeamos os 16 bytes do wrapper mínimo para
1 parâmetro PARAM inteiro.

Etapa 4 - Inspeção do mov imediato 32 bits (parâmetro FIX)
----------------------------------------------------------
Para parâmetros FIX, o wrapper precisa mover uma constante
inteira diretamente para o registrador antes de chamar f.
Inspecionamos os bytes de movl $10, %edi:

  bf 0a 00 00 00   mov $0xa, %edi

Opcode bf seguido de 4 bytes da constante em little-endian.
Não usa prefixo 48 pois int é 32 bits.



Etapa 5 - Implementação e teste: parâmetros FIX
------------------------------------------------
Adicionamos suporte ao tipo FIX em cria_func. Para cada
parâmetro FIX, o código gerado emite:

  bf + 4 bytes   mov $constante, %edi   (1º parâmetro)
  be + 4 bytes   mov $constante, %esi   (2º parâmetro)
  ba + 4 bytes   mov $constante, %edx   (3º parâmetro)

A constante é embutida em little-endian via memcpy.
Parâmetros PARAM continuam sem instrução adicional.

Etapa 6 - Inspeção do mov indireto (parâmetro IND)
---------------------------------------------------
Para parâmetros IND, o wrapper precisa carregar o endereço
da variável em %rax e então ler seu valor corrente.
Inspecionamos os bytes gerados:

  48 b8 + 8 bytes   movabs $endereço_var, %rax   (carrega ponteiro)
  8b 38             mov (%rax), %edi              (1º parâmetro)
  8b 30             mov (%rax), %esi              (2º parâmetro)
  8b 10             mov (%rax), %edx              (3º parâmetro)

Total por parâmetro IND: 12 bytes (10 do movabs + 2 do mov indireto).
O valor lido é sempre o corrente no momento da chamada.

Etapa 8 - primeira tentativa
de correção de erros: perda de PARAMs ao reposicionar argumentos
-----------------------------------------------------------------------
Ao testar PTR_PAR com memcmp (FIX + PARAM + PARAM), ocorreu
segmentation fault. O problema: ao emitir o FIX para %rdi,
o valor PARAM que havia chegado em %rdi era perdido antes
de ser reposicionado.

Conforme o aviso no enunciado:
"a localização dos parâmetros não amarrados recebidos pela
função gerada pode não ser a mesma para a chamada à função
original. Cuidado para não perder o valor desses parâmetros!"

Solução: antes de emitir qualquer FIX ou IND, reposicionar
todos os PARAMs de trás para frente (do último para o primeiro),
evitando sobrescrever valores ainda necessários. Pra isso,
mapeamos os bytes de mov entre registradores de 32 e 64 bits.



Etapa 9 - Correção do bug de reposicionamento e suporte a PTR_PAR
-----------------------------------------------------------------
Corrigimos o bug identificado na Etapa 8 e adicionamos suporte
completo a PTR_PAR. A solução foi dividir a geração de código
em dois passos:

Passo 1 — reposicionar PARAMs de trás para frente:
  Antes de emitir qualquer FIX ou IND, percorremos os parâmetros
  do último para o primeiro. Para cada PARAM, calculamos em qual
  registrador ele chegou (contando os PARAMs anteriores) e
  emitimos um mov reg->reg se necessário.

  Bytes dos movs entre registradores usados:
  64 bits (PTR_PAR): 48 89 fe/fa/f7/f2/d7/d6
  32 bits (INT_PAR): 89 fe/fa/f7/f2/d7/d6

Passo 2 — emitir FIX e IND normalmente:
  PTR_PAR + FIX: 48 bf/be/ba + 8 bytes do ponteiro
  PTR_PAR + IND: 48 b8 + 8 bytes + 48 8b 38/30/10
